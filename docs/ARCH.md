# Архитектура bOS

## Загрузка

bLOADER — приложение UEFI для x86-64. Оно загружает ELF-ядро из
`EFI/bOS/kernel.bin` и, если доступен, архив `EFI/bOS/initrd.img`.
Загрузчик передаёт ядру карту памяти, параметры framebuffer и адрес архива
в структуре `BootInfo`, завершает UEFI Boot Services и вызывает точку входа ядра.
Если в образе ядра не задан UUID, загрузчик формирует UUIDv8 из SHA-256
файла ядра. Один и тот же файл получает один и тот же UUID.

## Оболочка и файловая система

Ядро запускает bSH. Оболочка опрашивает последовательный порт COM1 и
клавиатуру PS/2. Вывод поступает в COM1 и, если доступен, в framebuffer GOP.

VFS монтирует ramfs в корне и импортирует файлы из initrd. При загрузке
создаются `/system`, `/users` и `/applications`. Сеанс bSH начинается в
`/users/default`.

При подключении одного подготовленного диска VirtIO ядро проверяет образ
bFS и монтирует его в `/users`. Транспорт опрашивает legacy PCI-очередь,
а bFS загружает том размером 4–32 МиБ в RAM. `sync`, `reboot` и `halt`
записывают изменённые блоки и выполняют сброс буфера устройства. При отсутствии
диска или ошибке проверки используется RAM, а bSH сообщает режим при старте.
bFS не ведёт журнал, поэтому аварийное выключение может повредить том.

## Пользовательские программы

Обычная загрузка запускает `/applications/native-init.bh` как PID 1 в ring 3.
Он создаёт native-shell, собирает завершившихся/осиротевших детей и перезапускает
оболочку. Прежняя bSH работает только как recovery (UEFI параметр `recovery`
или marker `/system/recovery` в initrd, флаг сборки `--recovery`).

Рабочий process runtime находится в `user.rs`, не в старых proc/sched заглушках.
На BSP до 64 записей процесса, отдельные CR3 и таблицы fd, round-robin 10 мс.
Полный trap context сохраняется и на timer, и на syscall; блокирующие read/write/
waitpid сохраняются как ожидающие операции. При отсутствии готовых задач CPU
спит в hlt. GPR/x87/SSE сохраняются; AVX отключён. Ядро невытесняемое.

spawn наследует stdio и явные перенаправления. Arc<Handle> даёт общие открытые
описания файлов и endpoints pipe; dup2 разделяет позицию. Pipe — кольцо 4096,
атомарный write до PIPE_BUF, EOF после последнего writer, EPIPE без readers.
Файлы закрываются при exit/fault, память ребёнка освобождается после waitpid.
Сироты передаются PID 1. ABI и ограничения: [abi.md](abi.md).

Нативная оболочка умеет запуск файлов, echo, cat, cat FILE | wc -c и sync.
argv/env, независимый cwd, полноценный job control, SMP и user permissions
ещё не реализованы. Ctrl-C перезапускает сеанс оболочки, сохраняя PID 1.
Ввод serial и PS/2 сейчас опрашивается из BSP планировщика; USB отсутствует.

## Блочное хранилище

`data_disk` выбирает VirtIO, иначе AHCI, иначе NVMe-диск с меткой bOS-users. Транспорт
фиксируется до монтирования; bFS использует единые read/write/flush.
AHCI реализует IDENTIFY, READ/WRITE DMA EXT, FLUSH CACHE EXT, bounded polling,
проверку границ и отказ после ошибки/таймаута. Дескрипторы и bounce buffer
находятся в постоянной DMA-области ниже 4 ГиБ. После таймаута память DMA
не освобождается даже при неудачной остановке контроллера.

Для SATA пока поддержан один выделенный raw bFS-диск с 512-байтными секторами, без GPT,
NCQ, hotplug и автоматического reset/retry. Это не полная поддержка хранилища
E7270. Формат всё ещё bFS v1, образ кэшируется целиком, журнала нет.
Реализация основана на [Intel AHCI 1.3.1](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/serial-ata-ahci-spec-rev1-3-1.pdf).

### NVMe

NVMe transport использует admin SQ/CQ и одну I/O SQ/CQ по 32 элемента,
с одним незавершённым запросом. Completion phase меняется при wrap;
проверяются command ID, queue ID, status и fatal bit. IRQ не используются.
PCI BAR отображается в отдельную supervisor-only NX/uncached область,
в том числе когда UEFI назначает MMIO выше 4 ГиБ. DMA находится в постоянных
выровненных страницах ядра; после timeout эта память не освобождается.

Identify перечисляет первые 1024 active namespaces и выбирает том с меткой
bOS-users, не записывая на диск при probe. LBA 512–4096 байт без metadata/PI
преобразуется в общий интерфейс 512-байтных секторов. Частичная запись в
больший native LBA сохраняет соседние данные через read/modify/write под
блокировкой устройства. Размер запроса ограничен MDTS и bounce buffer
64 КиБ; PRP2 содержит второй адрес либо PRP list. Flush отправляется SSD.

Это пока polling transport одного диска, без MSI-X, reset/retry, hotplug,
GPT и проверки на физическом SSD. Контроллеры с очередями менее 32 элементов
или минимальной страницей больше 4 КиБ не поддержаны. Блокировка и ожидание
I/O рассчитаны на текущий BSP runtime и требуют изменения перед SMP.
Регистры и команды: [NVMe specifications](https://nvmexpress.org/specifications/).

## Ethernet

При запуске bSH ядро перечисляет PCI-устройства и выбирает одну карту
с поддерживаемым идентификатором. Драйверы Intel 82540EM/82574L и
Realtek RTL8139 обслуживают DMA-очереди опросом. Они передают Ethernet-кадры
в smoltcp, который обрабатывает ARP, IPv4, DHCPv4 и ICMP. Оболочка опрашивает
сеть во время ожидания ввода, в том числе для продления аренды DHCP.

`ifconfig` показывает состояние линии, MAC, адрес IPv4 и шлюз.
`ifconfig static <IPv4/prefix> [gateway]` переключает интерфейс на ручную
настройку, `ifconfig dhcp` возобновляет получение адреса по DHCP.
`ping <IPv4>` отправляет один запрос с таймаутом. Версия 0.5.0 проверена
в QEMU. Список проверенных моделей приведён в [README](../README.md#ethernet-в-bsh).
